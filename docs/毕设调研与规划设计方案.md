# 第二部分 规划设计方案

## 2.1 需求分析（论文第 3 章素材）

### 2.1.1 业务背景与痛点

中小型商超（面积 100–500㎡，SKU 500–5000，员工 3–15 人）普遍存在：① 库存靠脑记/Excel，账实不符、临期损耗；② 进货无凭据链条，月底对账靠翻聊天记录；③ 销售与库存脱节，盘点差异无法追溯；④ 往来账款不清（对供应商应付、对团购客户应收均缺台账）；⑤ 经营决策无数据（不知畅销滞销与毛利）；⑥ 成品软件错位（SaaS 年费+数据在云端，大型 ERP 功能过剩）。

### 2.1.2 核心需求

| # | 需求 | 优先级 |
|---|---|---|
| 1 | 商品档案管理（分类、条码、单位、进售价、是否启用批次效期） | P0 |
| 2 | 采购进货：采购订单 → 采购入库（支持分批到货）→ 库存增加 → 应付账款 | P0 |
| 3 | 销售管理：销售出库（含简化 POS 收银）→ 库存减少 → 应收/收款核销 | P0 |
| 4 | 库存管理：实时库存、出入库流水、盘点、库存预警（下限 + 临期） | P0 |
| 5 | 供应商/会员档案与往来台账（应付 + 应收对称） | P0 |
| 6 | 统计报表：销售统计（**含毛利**）、畅销排行、库存预警表、往来对账表 | P1 |
| 7 | 批次与保质期管理（FEFO 出库） | P1 |
| 8 | 退货管理：采购退货（冲应付）、销售退货（库存回增 + 退款/冲应收） | P1 |
| 9 | 系统管理：用户/角色/菜单/数据权限 | P0 |
| 10 | 期初数据导入（Excel 批量导入商品与期初库存） | P1 |

### 2.1.3 系统边界（不做什么 —— 防过度设计）

- ❌ 不做多门店/**多仓库**——**仅单仓库**（库存表无仓库维度）
- ❌ 不做线上商城、小程序、外卖对接
- ❌ 不做促销规则引擎（仅会员等级折扣）
- ❌ 不做真实支付通道、发票税控、小票打印机硬件适配
- ❌ 不做完整财务总账（只做应收应付台账与核销）
- ❌ 不做复杂审批工作流引擎（仅单据状态流转）
- ❌ 不做收银交班/日结对账、称重散称商品、多单位换算
- ✅ 做赊销应收：零售现款为主，团购/熟客赊账纳入应收台账

## 2.2 功能模块设计

```
中小型商超进销存管理系统
├── 基础资料管理：商品管理 / 供应商管理 / 会员管理
├── 采购管理：采购订单（草稿/已审/部分执行/已执行/作废）/ 采购入库单 / 采购退货单
├── 销售管理：销售出库单（POS，保存即生效）/ 销售退货单 / 收款登记与应收核销（一对多）
├── 库存管理：实时库存查询 / 出入库流水台账 / 库存盘点 / 库存预警（下限+临期）
├── 往来账款（轻财务，应收应付对称）：应付台账+付款核销 / 应收台账+收款核销 / 对账单
├── 统计报表：销售统计（含毛利）/ 畅销滞销排行 / 采购与往来汇总 / 库存预警报表
└── 系统管理（★ RuoYi 原生复用）：用户角色菜单部门 / 数据权限 / 字典 / 操作与登录日志 / 代码生成器
```

层级说明：基础资料是数据底座；采购/销售是库存变动与往来的两大入口；库存不直接录入变动，全部由单据驱动（账实可追溯）；报表只读不写。

## 2.4 数据库设计（以实际落库为准）

### 2.4.1 全局规范

1. 前缀 `jxc_`，utf8mb4 / utf8mb4_general_ci，InnoDB，**不使用物理外键**（逻辑关联，RuoYi 风格）
2. 主键 `id BIGINT AUTO_INCREMENT`；全部表含 `create_by/create_time/update_by/update_time/remark`
3. 金额 `DECIMAL(18,2)`，数量与单价 `DECIMAL(18,4)`，禁止 FLOAT/DOUBLE
4. 单号 `VARCHAR(32) NOT NULL UNIQUE`，规则 `前缀+yyyyMMdd+3位流水`
5. `jxc_stock.batch_no` **NOT NULL DEFAULT ''**（规避唯一索引 NULL 陷阱）
6. 索引覆盖：临期预警(expiry_date)、流水追溯((product_id,batch_no)/(biz_type,biz_id))、单据列表((order_no)唯一+status+create_time)、往来核销((supplier_id,status)/(member_id,status)/(bill_type,bill_id))

### 2.4.2 表清单（19 业务实体 / 24 物理表）

| 表名 | 说明 | 关键字段 |
|---|---|---|
| `jxc_product_category` | 商品分类（树形） | parent_id, category_name, sort |
| `jxc_product` | 商品档案 | product_code(唯一), barcode, unit, purchase_price, sale_price, stock_min/max, shelf_life_days, enable_batch |
| `jxc_supplier` | 供应商 | supplier_code(唯一), contact, phone, payment_days（**无应付余额冗余字段**） |
| `jxc_member` | 会员 | member_no(唯一), level, discount, points, balance |
| `jxc_purchase_order`(+`_item`) | 采购订单 | order_no(唯一), supplier_id, total_amount, status；明细含 **received_qty**（分批到货） |
| `jxc_stock_in`(+`_item`) | 入库单（审核即执行） | in_no(唯一), source_type, source_no；明细含 batch_no, production_date, expiry_date, quantity, price |
| `jxc_purchase_return`(+`_item`) | 采购退货 | return_no(唯一), source_in_no；审核→库存减+**应付红冲** |
| `jxc_sale_order`(+`_item`) | 销售单/POS（保存即生效） | sale_no(唯一), member_id, actual_amount, received_amount, pay_status；明细含 batch_no, **cost_price/cost_amount 成本快照** |
| `jxc_sale_return`(+`_item`) | 销售退货 | return_no(唯一), source_sale_no；库存**按原批次回增** + 退款/应收红冲 |
| `jxc_stock_out`(+`_item`) | 出库单（**仅盘亏/采购退货**，销售出库由销售单驱动） | out_no(唯一), source_type, source_no |
| `jxc_stock` | 实时库存（**唯一校验依据**） | product_id, **batch_no NOT NULL DEFAULT ''**, expiry_date, quantity, cost_price；唯一键(product_id,batch_no) |
| `jxc_stock_flow` | 库存流水（只增不改） | change_qty, **balance_qty 批次结存快照**, biz_type, biz_id |
| `jxc_stock_check`(+`_item`) | 盘点单 | 明细 book_qty/actual_qty/diff_qty + **gen_in_no/gen_out_no** |
| `jxc_payable` / `jxc_receivable` | 应付 / 应收台账（**完全对称**） | amount, paid_amount, balance, status |
| `jxc_payment`(+`_item`) | 收付款单 + 核销明细 | 主表 pay_no(唯一)+target_type；明细 **bill_type/bill_id/writeoff_amount（一对多核销）** |
| `sys_*`(18) / `QRTZ_*`(11) / `gen_*`(2) | RuoYi 原生 | 基座自带 |

### 2.4.3 核心链路（ER）

```
jxc_supplier ─1:N─ jxc_purchase_order(_item) ─分批到货─▶ jxc_stock_in(_item)
      │                                                        │审核（同事务）
      │                                          stock(+)、stock_flow(+)、jxc_payable(+)
      │◀── jxc_payment(SUPPLIER) ──jxc_payment_item 一对多核销── jxc_payable
jxc_purchase_return ─审核─▶ stock(−)、flow(−)、payable 红冲(−)

jxc_member ─1:N─ jxc_sale_order(_item) ─保存即生效─▶ stock(− 按 FEFO 拆批)、flow(−)、成本快照、jxc_receivable(+若赊销)
      │◀── jxc_payment(MEMBER) ──jxc_payment_item── jxc_receivable
jxc_sale_return ─审核─▶ stock(原批次回增)、退款/应收红冲
jxc_stock_check ─处理─▶ 盘盈生成 stock_in / 盘亏生成 stock_out（gen_in_no/gen_out_no 回写）
```

### 2.4.4 单据状态机与业务规则（论文第 4 章状态图素材）

| 单据类型 | 状态机 |
|---|---|
| 采购订单 | 草稿 → 已审核 → 部分执行/已执行 → 已作废（仅草稿可作废） |
| 入库/出库/退货单 | 草稿 → 已审核（**审核即执行**）→ 仅草稿可作废 |
| POS/销售单 | 保存即已审核已执行 |
| 盘点单 | 草稿 → 已审核（生成调整单） |

**业务规则 10 条**：① 库存变动只发生在审核时刻，开单不占用库存；② 负库存校验以 `jxc_stock` 为唯一依据，原子语句 `UPDATE ... WHERE quantity>=?` 防并发超扣；③ 已审核单据不可作废，纠错只能红字/退货单；④ 采购退货→库存减+应付红冲，销售退货→原批次回增+退款/应收红冲；⑤ **个别计价法**：按所扣批次实际进价快照成本；⑥ 批次商品按 FEFO 出库，可拆多批次行；⑦ 核销支持一对多与部分核销；⑧ 往来余额由台账聚合，不冗余；⑨ 临期预警 = `expiry_date − today ≤ 阈值`，下限预警 = `quantity ≤ stock_min`；⑩ 同一事务内完成"单据状态 + 库存 + 流水 + 台账"四处写入。
